# 入力エラー表示仕様

## 概要

`/word ranking` 実行時に、日付入力エラーと `limit` 入力エラーが同時に存在する場合、片方だけでなく両方のエラーを表示します。

## 対象コマンド

- `/word ranking`

## 現状の問題

現在の実装では、入力検証の途中で `ValueError` が発生した時点で処理が中断されます。

そのため、以下のような複数の不備が同時にある場合でも、最初に検出されたエラーだけが表示されます。

- `from` または `to` が不正な日付
- `limit` が許容範囲外

## 期待する動作

複数の入力エラーがある場合、Discord への返信にすべてのエラーを改行区切りで表示します。

表示例:

```text
入力内容に問題があります:
- 日付は YYYY-MM-DD 形式で指定してください。
- limit は 100 以下で指定してください。
```

エラーがない場合は、従来通りランキング集計を実行します。

## 検証方針

`/word ranking` では、ランキング取得前に入力値を個別に検証します。

検証項目:

- `from` / `to` の日付形式
- `limit` の範囲

各検証で発生したエラー文言を `list[str]` に追加します。

エラーが 1 件以上ある場合は、DB 集計処理を行わず、エラー一覧を `ephemeral=True` で返信します。

## 実装方針

`services.stats` に、ランキング入力をまとめて検証する関数を追加します。

想定関数:

```python
def validate_ranking_options(
    *,
    from_date: str | None,
    to_date: str | None,
    limit: int,
) -> tuple[int | None, list[str]]:
    ...
```

戻り値:

- `validated_limit`: 正常な場合は検証済み `limit`、不正な場合は `None`
- `errors`: 入力エラー文言の一覧

日付検証は既存の `parse_detection_date_range()` を使い、検索時と同じルールで確認します。

`commands/word.py` の `/word ranking` は、以下の順で処理します。

1. 監視ワード存在確認
2. `validate_ranking_options()` で入力エラーを収集
3. エラーがあれば一覧表示して終了
4. エラーがなければランキング集計を実行

## テスト方針

以下のテストを追加します。

- 不正な日付と過大な `limit` が同時に指定された場合、両方のエラーが取得できること
- 日付のみ不正な場合、日付エラーだけ取得できること
- `limit` のみ不正な場合、`limit` エラーだけ取得できること
- 正常入力の場合、エラーが空で検証済み `limit` が返ること

## 非対象

- `/word stats` のエラー集約
- Discord UI 上の入力補完や入力制限
- 日付形式そのものの変更
